# Generic OIDC Sign-in Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Google-only OAuth mode with a generic, multi-provider OIDC mode (authentik, Google, …), auto-redirect for a single new-style provider, and a `/?login` break-glass — without changing behavior for existing configs.

**Architecture:** `config.js` normalizes a provider list (`oidcProviders`) from `.env`/`config.json`/legacy Google keys. A new dependency-free `oidcAuth.js` does discovery, code+PKCE+nonce, token exchange and id_token claim checks per provider. `server.js` mounts per-provider routes (plus legacy `/api/auth/google/*`), the break-glass password route, and an extended `/api/auth/info`. The web login becomes a pure `decideLogin()` plus DOM in `main.ts`.

**Tech Stack:** Node 22 ESM, Fastify, vitest, TypeScript web client, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-11-oidc-auth-design.md` (read it; this plan argues from it).

## Global Constraints

- Additive only: every existing key, route, redirect URI and legacy-Google UX keeps working (spec §10). Only accepted change: a leftover `TMUXIFIER_PASSWORD_HASH` enables `/?login` password in OIDC mode.
- No new npm dependencies. Node builtins + `fetch` only.
- `loadConfig` stays pure: read only the `env`/`cwd` it is given.
- Provider id regex: `^[a-z0-9][a-z0-9-]{0,31}$`; env key segment = id upper-cased, `-` → `_`.
- Issuer and discovered endpoints must be `https://`, except a loopback host (`127.0.0.1`, `::1`, `localhost`) which may be `http://`.
- Every outbound fetch: 10 s `AbortSignal.timeout(10000)`; discovery body capped at 64 KiB.
- `TMUXIFIER_ALLOWED_EMAILS` required in OIDC mode; exact, lower-cased match.
- No real domains/emails in code, tests or docs: `example.com`, `you@example.com`.
- Conventional commits (`feat(auth): …`).

## Review Focus

1. Legacy Google `.env` boots and keeps `/api/auth/google/callback` as `redirect_uri`, no auto-redirect → Task 1 + Task 3 + Task 4 tests.
2. Google `iss` arriving as bare `accounts.google.com` is accepted for the Google issuer only → Task 2 test `accepts bare google iss only for google`.
3. Callback with a state cookie minted for provider A replayed against provider B's callback → rejected `?error=state` → Task 3 test.
4. Provider discovery down at boot → server still boots, password/passkey break-glass works, that provider's login redirects `/?error=provider` → Task 3 test.
5. Logout then reload → no redirect loop (signed-out page), while a 401 expiry does auto-redirect → Task 4 `decideLogin` tests.
