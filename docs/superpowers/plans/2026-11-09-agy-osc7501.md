# Antigravity CLI (agy) Agent State Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Antigravity CLI (`agy`) panes report working / blocked / done / idle in Tmuxifier like Codex and pi panes do (issue #4).

**Architecture:** No new mechanism. The shipped OSC 7501 pane reporter (v1.24.78) already folds agy's records correctly; this patch only (1) lets the reporter attach to panes whose command is `agy`, (2) teaches the server and the web client the `agy` agent kind and its label, and (3) makes setup add the rc line that turns agy's reporting on inside tmux.

**Tech Stack:** Node ESM server (`src/server/*.js`), stdlib python3 box asset, TypeScript web client, vitest.

**Spec:** none (the operator asked for a plan only). The facts this plan argues from are the recording committed in `266d663`: `test/fixtures/osc7501-pane-trace.jsonl` lines 1491-2321, described row by row in `test/fixtures/README-osc7501-pane-trace.md` (scenarios (q)-(ad) and the "agy's record model" note), and pinned by the `AGY` / `AGYAUTH` trails in `test/osc7501Replay.test.js`.

## Decisions (made from the recording)

- **D1. Kind key `agy`, label `Antigravity`.** The key is the pane command (`#{pane_current_command}` = `agy`) and equals the setup tool id; agy's own `app=antigravity` is not used as a key. Pattern: `^agy(-|$)`, the same string in the python asset and the server.
- **D2. `kind=auth` keeps mapping to the `elicitation` cause. No code change.** In the recording (line 2263) the `auth` block is agy's "Select login method" menu: the agent waits for the operator to choose, which is what `elicitation` already means in the marker vocabulary (input requested from the operator that is neither a tool approval nor a model question), and it ends on `idle` (2312) like any other block. A dedicated `auth` cause would widen the closed marker vocabulary (`AGENT_MARK_CAUSES` in `status.js`, `AgentCause` in the web client, the MCP tool text) for a screen that appears once per box. The `AGYAUTH` replay trail already pins `blocked/elicitation`.
- **D3. agy never sends `state=clear`; no code change.** Leaving agy ends on `idle` (lines 2198, 2312), so the marker reads `ready/stop` until the reporter loop detaches the pane (three non-matching 2 s passes) and its listener bare-clears the marker at EOF. That path exists and is covered by the reporter's own suites; it is checked live after this plan.
- **D4. The rc line is unconditional**, like pi's: `export AGY_CLI_OSC7501=on # tmuxifier-osc-agy`, in the same three files under the same delete-then-append rule, written after the pi line.

## Global Constraints

- The pane-command pattern is exactly `^agy(-|$)` in both `OSC_AGENTS` (python) and `agentKindOf` (JS). `agy-x` is an agent; `agyx` is not.
- The label is exactly `Antigravity` (capital A, no "CLI") wherever an agent kind is turned into words.
- The rc line is exactly `export AGY_CLI_OSC7501=on # tmuxifier-osc-agy`; its tag is `tmuxifier-osc-agy`.
- The installer script text interpolates nothing: the only shell variables it may contain are `$HOME`, `$DIR`, `$$`, `$rc`, and no `${`.
- Do not change `KIND_CAUSE`, `CAUSE_KIND`, `next_action`, `Records` or anything else in the asset's fold; do not touch the fixture, its README or `test/osc7501Replay.test.js` (already committed).
- Tests use real code, not mocks. Write the failing test first and watch it fail.
- Never run `npm run build`. The checks are `npx vitest run <file>` and `npm run typecheck`.
- Committed text carries no real hostnames, IPs, domains or emails.
- Conventional-commit messages; end each commit message with the line `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- `CLAUDE.md` and `AGENTS.md` are kept identical in the passages this plan edits.

## Review Focus

1. **An operator's own `AGY_CLI_OSC7501` line.** A box whose rc file already carries an untagged `export AGY_CLI_OSC7501=off` must keep that line untouched; only lines ending in the tag are ever deleted. (Test in Task 2.)
2. **Lookalike commands.** `agyx`, `agy2` and `mcp-agy` must not read as an agent, in JS and in the asset. (Tests in Task 1.)
3. **A rerun must not stack lines.** Two setup runs leave exactly one agy line and exactly one pi line per rc file. (Test in Task 2.)
4. **An unknown kind from a newer server must not break an older label map.** `agentLabel` falls back to `Claude` for kinds it does not know; adding `agy` must go through the maps, not around the fallback. (Tests in Task 1 assert the label through the public builders.)
5. **A missing rc file stays missing.** `.bashrc` / `.zshrc` are not created for the agy line; only `.profile` is. (Test in Task 2.)
